🚀 METHOD 5 COMPLETE REFERENCE: LOW-LEVEL RAW GAZEBO SIM SERVICE CALLS
================================================================================

1. ARCHITECTURAL OVERVIEW
--------------------------
Every high-level spawning workflow in Gazebo Harmonic eventually maps to a singular,
unified backend bridge endpoint. Whether using Method 1 (GUI Drag-in), Method 2 (CLI 
Create Node), or Method 3 (Launch File), the final intent is always processed by an 
underlying `gz-transport` network interface mechanism. 

This mechanism directly listens to a dynamic, case-sensitive system service path structured 
exactly as: `/world/<world_name>/create`.

2. THE UNDERLYING SERVICE ANATOMY
-----------------------------------
A direct command-line call to the raw simulation factory utilizes the following properties:

• Service Endpoint:   /world/<world_name>/create
• Request Message:   gz.msgs.EntityFactory   -> Houses blueprint parameters for file source, entity name, and pose profiles.
• Response Message:  gz.msgs.Boolean         -> Returns 'true' upon proper execution or 'false' if it fails.
• Request Body Type: Protobuf Text Format    -> Inline attributes passed cleanly via single-quote brackets.

3. DISCOVERING ACTIVE SYSTEM WORLD ENTITIES
--------------------------------------------
When working with standard pre-built environments (e.g. `empty.sdf`), Gazebo injects internal 
SDF layout names that might differ from your raw filenames. To find the exact runtime identifier 
needed to form the service string path, execute:

  $ gz service -l

This queries the active network, revealing your current target world descriptor string (e.g. `empty`, `world`, or `default`).

4. THE EXECUTABLE SYNTAX WRAPPER
----------------------------------
To programmatically inject your converted SDF structural robot model inside the active `empty` simulation matrix, run:

  gz service -s /world/empty/create \
    --reqtype gz.msgs.EntityFactory \
    --reptype gz.msgs.Boolean \
    --timeout 5000 \
    --req 'sdf_filename: "/mnt/ubuntu_data/ROS2/GAZEBO/03_spawn_urdf_robot/0_Spawning_Robot/method_4_A_SDF_Direct_Embedding_robot.sdf", name: "my_robot", pose: {position: {z: 5.0}}'

5. SYSTEM DIAGNOSTIC TRAPS TO AVOID
------------------------------------
• Syntax Flaws: Ensure double dashes (`--timeout`, `--req`) are used. Single dashes cause parsing exceptions.
• Case-Sensitivity: System services strictly separate paths by capitalization layout profiles. Match world hooks exactly.
• File References: Always provide absolute system directory paths pointing to the target converted model asset profile rather than the global environment world map configuration.
